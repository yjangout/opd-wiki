# Agentic OPD

把 OPD 用到多轮智能体任务（工具调用、网页浏览、软件工程等）上。

## 为什么需要

多轮智能体任务的奖励比单轮推理更稀疏：一条轨迹可能有十几轮、上万个 token，最后只有一个"成功 / 失败"。GRPO 分不清"一次调对"和"绕路调对"，也分不清十轮里是哪一轮出了错，见[L4 Agentic RL](../tutorial/l4-agentic.md)。

OPD 的逐 token 信号恰好能提供细粒度的信用分配。2607.24720 在受控的多轮规划环境里发现，在数据质量低、任务长的条件下，OPD 的有效区间比 GRPO 更宽，作者认为原因是 OPD 的更新方向更一致。<span class="unverified">⚠️</span>

## 和单轮 OPD 的区别

| | 单轮 | 多轮智能体 |
|---|---|---|
| 轨迹里有哪些 token | 只有模型写的 | 模型写的 + 工具返回 + 用户（模拟器）发言 |
| 哪些 token 参与训练 | 全部回答 | 只有模型写的，其余要 mask |
| 教师看到的上下文 | 题目 + 学生回答 | 题目 + 学生的全部动作 + 环境的全部反馈 |
| 学生走错之后 | 前缀偏离，信号逐渐失真 | 环境状态也变了（调错工具拿到无关结果），后续信号失真得更快 |
| 采样成本 | 生成 | 生成 + 环境执行 + 用户模拟器 |

## 主要问题与代表工作

### 学生走错之后，教师信号失效

- **STRIDE**（2609.14636）：发现有效的监督集中在每一轮的前缀，学生第一次做出错误动作时教师就不再背书。做法是：教师的累计 logprob 低于阈值时**提前停止** rollout，并缓存高质量前缀，从**最弱的正确轮次重新开始**，形成一个逐步覆盖后续轮次的课程。报告在 τ²-bench retail 上提速 3.73 倍，效果追平完整 OPD 并超过 30B 教师；多教师跨领域训练下提速 4.51 倍。<span class="unverified">⚠️</span>
- **State-OPD**（2610.13238）：把教师监督建立在交互状态上，在高熵状态处采样多个完整的"推理 + 动作"回应。<span class="unverified">⚠️</span>

### 按轮次加权与课程

- **SOD**（2605.07725）：针对小模型智能体，按每一步的师生差异重新加权教师的指导，避免工具调用引发的连锁漂移。报告中 0.6B 学生用 14B 教师时，加权能找回被容量差距吃掉的增益。<span class="unverified">⚠️</span>
- **ATOD**（2606.27814）：按轮次退火的 OPD，并与 RL 结合。作者指出 OPD 早期提升很快，但学生接近教师后收益饱和。<span class="unverified">⚠️</span>
- **TCOD**：从短到长的轨迹深度课程，缓解多轮 KL 的不稳定。<span class="unverified">⚠️</span>
- **Curriculum Turn-level Guidance**（2606.15912）：轮次级别的课程指导。<span class="unverified">⚠️</span>

### 过度调用工具

多教师 OPD 会让学生更爱调用工具，在不该调用时也调用，见[多教师 OPD](multi-teacher.md)。

### 学到的是规划模式还是具体流程

2607.24720 的发现 <span class="unverified">⚠️</span>：

- 用思维链显式建模状态转移（构建世界模型），能改善长程泛化；
- 少量长程数据就很有效，只有原子技能不足以组合泛化；
- 把学生没见过的具体流程硬蒸进去，会破坏学生原有的世界模型，新知识也没学到。

## 可参考的实现

- **tinker-cookbook** 有现成的多轮工具调用 OPD 配方（Harbor 沙箱，如 Terminal-Bench），唯一的训练信号是对教师的 KL，见 [slime 与 Tinker](../frameworks/others.md)；
- **verl** 的多轮 agent loop 和 OPD 分别都有官方支持，但截至 2026 年 10 月没有两者组合的官方示例，需要自己验证。
