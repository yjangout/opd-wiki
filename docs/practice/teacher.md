# 教师怎么选

教师是 OPD 里最重要的变量。选错教师，后面怎么调都很难救回来。

## 四条标准

| 标准 | 为什么 | 怎么判断 |
|---|---|---|
| **同 tokenizer** | 标准 OPD 要逐 token 对比 logprob，词表必须一致 | 同一个模型家族通常就满足；跨家族要用 [GOLD / ULD](../frontier/new-domains.md) |
| **思维模式兼容** | 不兼容时，师生高概率 token 的交集太小，训练飞轮转不起来 | 开训前测一次 top-k 重叠率；优先选和学生同源的教师 |
| **有增量能力** | 只是参数更多的同源教师，局部分布和学生几乎一样，教不出新东西 | 教师最好经过 RL 或专门训练，在目标任务上明显强于学生 |
| **尺寸适中** | 差距太大，学生吸收不了（容量差距） | 经验上 2–5 倍；同尺寸的专家模型也可以 |

## 教师不必很大

不少研究里，教师和学生差距很小，甚至一样大 <span class="unverified">⚠️</span>：

| 研究 | 学生 | 教师 | 发现 |
|---|---|---|---|
| Revisiting OPD <span class="verified">✅</span> | Qwen2.5-7B-Instruct | OpenThinker3-7B | 教师和学生一样大，教师经过专门训练就有效 |
| Rethinking OPD <span class="verified">✅</span> | 1.5B–1.7B | 4B–7B | 经 RL 训练、同源的小教师，比分数更高的大教师更好 |
| Thinking Machines <span class="verified">✅</span> | Qwen3-8B-Base | Qwen3-8B / 32B | 有些实验里 8B 教师效果略好于 32B |
| SOD（2605.07725） | 0.6B | 4B 对比 14B | 换成 14B 教师，平均分反而下降 |
| Unmasking OPD（2605.10889） | 0.6B / 1.7B | 自蒸馏 / 外部教师 | 0.6B 时自蒸馏最好；到 1.7B，外部大教师才开始有竞争力 |
| 量化 OPD（2609.26708） | 0.6B（低比特） | 1.7B | 1.7B 教师让 GSM8K 提升 11–14 分；1.7B 以上学生，大教师比自蒸馏没有优势 |
| HF TRL <span class="verified">✅</span> | Qwen3-4B | 30B-A3B / 235B-A22B | 235B 教师强约 10 分，学生最终水平差不多，域外能力反而下降 |

结论：**教师的价值在于"有学生没有、但学生学得会的能力"，而不在于参数量。**

## 教师从哪里来

| 来源 | 适用场景 | 案例 |
|---|---|---|
| 同家族的更大模型 | 最常见的起点 | Qwen3 用 32B / 235B 教小模型 |
| 同尺寸或更大的 RL 专家 | 想把某个领域的 RL 成果搬给学生 | DeepSeek-V4、MiMo-V2-Flash 的领域专家 |
| 自己 RL 训练过程中的中间 checkpoint | 后续训练阶段让某些能力回退了 | Nemotron-Cascade 2 |
| 训练之前的原始模型 | 注入新知识后修复遗忘 | Thinking Machines 的个性化实验 |
| 学生自己（看到额外信息时） | 没有外部教师 | [自蒸馏](../frontier/self-distillation.md)：OPSD、SDPO |
| 闭源 API 模型 | 只能拿到文本 | [黑盒 OPD](../frontier/black-box.md)：GAD、rubric 打分；或者用来生成 off-policy 数据 |

## 多教师时：模式要兼容

用多个教师时，还要看教师之间是否兼容。2607.24720 在受控的多轮规划环境里发现 <span class="unverified">⚠️</span>：

- 教师的规划模式**兼容**：多教师 OPD 能带来跨环境的泛化；
- **部分重叠**：可以支持持续学习；
- **完全冲突**：会产生严重的干扰。

## 不要指望 OPD 教会"具体答案"

同一篇论文还发现：把学生完全没见过的具体流程硬蒸进去，不仅新知识没学到，还会破坏学生原有的世界模型。<span class="unverified">⚠️</span>

自蒸馏里的 "privilege illusion" 是同一类问题：教师看到了标准答案，学生学到的是"依赖标准答案的行为"，推理时却拿不到答案。

所以要区分两类东西：

- **可共享的行为**（推理方式、工具调用习惯、格式、纠错方式）：适合 OPD；
- **具体实例的答案或知识**：更适合通过数据（SFT、中训练）注入。

## 实操检查

- **教师温度固定为 1.0**：教师应该用原始分布打分。verl 会强制教师用温度 1.0，配置不同时只会打日志警告。<span class="verified">✅</span>
- **sanity check**：把学生设成和教师同一个模型，loss 应该接近 0（由于训练和推理引擎的数值差异，不会正好为 0）。<span class="verified">✅</span>
- **模板一致**：教师打分时看到的上下文必须和学生生成时完全一致。verl 直接用 token id 拼接 prompt 和回答，不经过"解码再编码"，保证了对齐，见[verl 源码走读](../frameworks/verl-walkthrough.md)。
