# 三种方法的数据长什么样

先说结论：**GRPO 和 OPD 的数据集里基本只有题目，回答是训练时由学生现场生成的。** 这是它们和 SFT 最大的区别。

下面用同一道数学题和同一个工具调用任务，把三种方法的数据摆在一起对比。

## SFT：题目和回答都事先写好

```json
{"messages": [
  {"role": "user", "content": "解方程 3x + 5 = 20"},
  {"role": "assistant", "content": "两边减 5，得 3x = 15，所以 x = 5。"}
]}
```

训练时学生在这段回答上逐个 token 学"下一个词"，每个 token 的权重都是 1。

## GRPO：题目 + 判分依据

### 磁盘上存的

以 verl 的格式为例（存成 parquet，一行一条）：

```python
{
    "data_source": "openai/gsm8k",       # 用来选奖励函数
    "prompt": [{"role": "user", "content": "解方程 3x + 5 = 20。最后把答案写在 \\boxed{} 里。"}],
    "ability": "math",
    "reward_model": {"style": "rule", "ground_truth": "5"},
    "extra_info": {"split": "train", "index": 0},
}
```

数据里没有回答，只有标准答案，供验证器判断对错。

### 训练时现场生成的

每道题让学生采 $G$ 条回答（这里 $G = 4$），验证器逐条打分，再在组内归一化：

| 学生回答 | 最终答案 | 奖励 | advantage |
|---|---|---|---|
| 两边减 5，得 3x = 15，所以 x = 5 | 5 | 1 | +0.87 |
| 两边减 5，得 3x = 25，所以 x = 25/3 | 25/3 | 0 | −0.87 |
| 3x = 20 − 5 = 15，x = 5 | 5 | 1 | +0.87 |
| 移项得 3x = 20 + 5，x = 25/3 | 25/3 | 0 | −0.87 |

**同一条回答里的每个 token 拿到的都是同一个数。** 第二条前面的"两边减 5"其实是对的，也跟着被扣了 0.87。

如果 4 条全错，奖励是 [0, 0, 0, 0]，advantage 全为 0，这道题这一步学不到东西。

## OPD：只有题目

### 磁盘上存的

```json
{"prompt": [{"role": "user", "content": "解方程 3x + 5 = 20"}]}
```

不需要标准答案，也不需要验证器，打分的是教师模型。实践中常常直接复用 GRPO 的数据文件，这样方便做"OPD + 结果奖励"的对照。

### 训练时现场生成的

学生生成一条回答，教师对整条回答做一次前向，给出每个已采样 token 的概率。为了好读，下表按词切分（实际按 tokenizer 的 token 切）：

| 学生采样的 token | 学生概率 | 教师概率 | $r_t = \ln(\text{教师}/\text{学生})$ | 含义 |
|---|---|---|---|---|
| 两边 | 0.80 | 0.85 | +0.06 | 教师略更认可，轻微强化 |
| 减 | 0.90 | 0.95 | +0.05 | 同上 |
| 5 | 0.95 | 0.97 | +0.02 | 几乎一致 |
| ，得 3x = | ≈ | ≈ | ≈ 0 | 一致 |
| **25** | 0.30 | **0.01** | **−3.40** | **算错的地方，被重重压低** |
| ，所以 | 0.90 | 0.30 | −1.10 | 教师更想接"等等，算错了" |
| x = | 0.95 | 0.90 | −0.05 | 一致 |
| 25/3 | 0.90 | 0.85 | −0.06 | 前文已经错了，教师也认可这个局部接得上的续写 |

和 GRPO 相比：

- **错误位置精确**：只有"25"和紧跟着的"，所以"被明显扣分，前面正确的步骤不受影响；
- **失败的轨迹照样能学**：不需要同组里有人做对。

这张表也暴露了 OPD 的两个已知局限：

- **最后一行**：前文已经错了，教师对错误的续写也给了高概率。这就是"越往后前缀越偏，教师信号越不可靠"；
- **"，所以"那一行**：教师其实想说"等等"，但 sampled-token 版本只会压低"，所以"，不会直接把"等等"抬上来。概率质量被压下去之后流向哪里，sampled-token 版本控制不了，见[估计粒度](../theory/estimators.md)。

想看真实模型上的数值，可以打开[verl 源码走读](../frameworks/verl-walkthrough.md)里的交互演示，它用一条真实的 GSM8K 样本展示了每个 token 的学生和教师 logprob。

## 多轮工具调用里的样子

工具调用的轨迹里混着三种 token：模型写的、工具返回的、用户说的。**只有模型自己写的 token 参与训练**，其余都用 loss mask 遮掉：

```text
[user]      帮我查明天新加坡的天气                              ← mask，不训练
[assistant] <tool_call>{"name":"get_weather",
              "arguments":{"city":"Singapore","date":"明天"}}</tool_call>       ← 训练
[tool]      {"error":"date 必须是 YYYY-MM-DD 格式"}              ← mask，不训练
[assistant] <tool_call>{"name":"get_weather",
              "arguments":{"city":"Singapore","date":"2026-10-20"}}</tool_call> ← 训练
[tool]      {"temp":"31°C","weather":"雷阵雨"}                   ← mask，不训练
[assistant] 明天新加坡 31°C，有雷阵雨，记得带伞。                 ← 训练
```

- **GRPO**：任务最终完成了，奖励为 1。三段 assistant 内容都拿到同一个正分，包括第一次填错格式的 `"明天"`；
- **OPD**：教师在 `明天` 这个 token 上概率很低（它会直接写日期），$r_t$ 明显为负；后面两段和教师一致，$r_t$ 接近 0。

| 段落 | token（示意） | 学生概率 | 教师概率 | $r_t$ |
|---|---|---|---|---|
| 第 1 次调用 | `"date": "` | 0.95 | 0.96 | +0.01 |
| | `明天` | 0.60 | 0.02 | **−3.40** |
| 工具返回 | `{"error": ...}` | — | — | mask |
| 第 2 次调用 | `2026-10-20` | 0.70 | 0.92 | +0.27 |
| 最终回答 | `明天新加坡 31°C……` | ≈ | ≈ | ≈ 0 |

## 汇总

| | 磁盘上存什么 | 训练时生成什么 | 每个 token 的权重 |
|---|---|---|---|
| SFT | 题目 + 标准回答 | 无 | 恒为 1 |
| GRPO | 题目 + 标准答案 / 判分规则 | 每题 $G$ 条学生回答 + 每条的分数 | 整条回答共用一个数 |
| OPD | 只有题目（另需部署教师模型） | 学生回答 + 教师对每个 token 的概率 | 每个 token 各自一个 $r_t$ |
| OPD + RLVR | 题目 + 标准答案 | 两者都有 | $r_t + \alpha \times$ 整条的分数 |

## 统一视角

在训练器看来，几种方法吃进去的都是"**一串 token + 每个 token 的权重**"。省略裁剪和重要性比，梯度都可以写成：

$$
\nabla \mathcal{L} = -\sum_t w_t \, \nabla_\theta \log \pi_\theta(y_t \mid x, y_{<t})
$$

| 方法 | $y$ 是谁写的 | $w_t$ |
|---|---|---|
| SFT | 数据集（人或教师） | $1$ |
| GRPO | 学生 | $\hat{A}_i$（整条回答相同） |
| OPD | 学生 | $r_t = \log \pi_T(y_t) - \log \pi_S(y_t)$（stop-gradient） |

区别只有两点：

1. **token 是谁写的**：SFT 是教师写的，GRPO 和 OPD 是学生自己写的；
2. **权重怎么来**：SFT 恒为 1，GRPO 看最终结果，OPD 由教师逐 token 打分。

在 verl 里，OPD 和 GRPO 可以共用同一份 parquet 数据。做多教师 OPD 时，`data_source` 字段还兼任路由，决定这道题交给哪个教师打分。
