# 三个评测集：先看整体区别

| | GPQA-Diamond | AIME 2026 | LiveCodeBench v6 |
|---|---|---|---|
| 考什么 | 研究生水平的物理、化学、生物选择题。挑的是领域专家能做对、外行上网查半小时也做不对的题 | 2026 年美国数学邀请赛，高中数学竞赛题 | 编程竞赛题，来自 LeetCode、AtCoder、Codeforces。v6 是 2025 年初新加的题，模型训练时大概率没见过 |
| 题量 | 198 | 30 | 175 |
| 答案形式 | 四选一的字母 | 0～999 的整数 | 一段 Python 程序 |
| 怎么判分 | 抽出最后一行的字母，和正确选项比 | 抽出 `\boxed{}` 里的数，按数值和标准答案比 | 在 Docker 沙盒里运行代码跑测试，全部通过才算对 |
| 属于五类中的 | ① 标准答案 | ① 标准答案 | ② 可执行验证 |

下面每个评测集各看一道真实的题：模型收到什么、输出什么、怎么判分。

## ① GPQA-Diamond

**输入**

```text
[指令] 回答下面的选择题，一步一步思考，最后一行必须写成 "ANSWER: 字母"（A/B/C/D 之一）

[题干] 一个自旋 1/2 粒子处于叠加态 0.5|↑⟩ + (√3/2)|↓⟩，|↑⟩ 和 |↓⟩ 是 σz 的本征态。
       求算符 10σz + 5σx 的期望值，保留一位小数。

A) 1.65
B) -0.7
C) 0.85
D) -1.4
```

**输出**：先有一段思考（866 字符，放在 reasoning 字段，不参与判分），然后是最终回答：

```text
⟨σz⟩ = 1/4 − 3/4 = −1/2
⟨σx⟩ = 2 · (1/2) · (√3/2) ≈ 0.866
⟨10σz + 5σx⟩ = 10(−0.5) + 5(0.866) = −5 + 4.33 ≈ −0.7

ANSWER: B
```

**判分**：从最后一行抽出 B，正确答案是 B，得 1 分。这题输入 235 token，输出 560 token。

!!! note "同一道题，答案字母可能不同"
    原始数据里每题只存了 1 个正确答案和 3 个干扰项，评测时才打乱排成 A～D。所以同一道题在不同评测框架里，正确答案的字母可能不一样。

## ① AIME 2026

**输入**

```text
[指令] 一步一步解下面这道题，答案放进 \boxed{}

[题目] Patrick 从学校步行去公园。他出发 1 小时后，Tanya 沿同一条路跑步出发，速度比 Patrick 快 2 英里/小时；
       Tanya 出发 1 小时后，Jose 骑车出发，速度比 Tanya 快 7 英里/小时。三人同时到达公园。
       学校到公园的距离是 m/n 英里（m、n 互质），求 m + n。

[结尾再提醒一次] 答案放进 \boxed{}
```

**输出**：思考 3317 字符，最终回答的推导大意如下：

```text
设 Patrick 速度为 p，则 Tanya 为 p+2，Jose 为 p+9，距离为 D
D/p = 1 + D/(p+2)  ⇒  D = p(p+2)/2
D/p = 2 + D/(p+9)  ⇒  D = 2p(p+9)/9
两式相等 ⇒ 9(p+2) = 4(p+9) ⇒ p = 18/5
D = 252/25 ⇒ m + n = 252 + 25 = 277

\boxed{277}
```

**判分**：抽出 `\boxed{}` 里的 277，用 `math_verify` 和标准答案 277 比较。它按数值比，所以写成 277.0 之类的等价形式也算对。这题输入 228 token，输出 2127 token。

## ② LiveCodeBench v6

这题来自 AtCoder。

**输入**

````text
[system] 你是 Python 专家。会给你一道题，写出能通过所有测试的程序，只返回程序。

[user]
### Question:
九九乘法表共 81 格，第 i 行第 j 列是 i×j。给定整数 X（1～81），
求这 81 个数里不等于 X 的那些数之和（同一个数出现在几格就算几次）。
输入：一行，X
输出：上面说的和
样例：X=1 → 2024；X=11 → 2025；X=24 → 1929

### Format: 从标准输入读，往标准输出写，代码放进 ```python 代码块
### Answer:
````

**输出**：思考 746 字符。模型想到全表之和是 45² = 2025，再减去「等于 X 的格子数 × X」，并用三个样例自己验算了一遍。最终回答：

```python
import sys

X = int(sys.stdin.readline())

total = 2025
count = sum(1 for i in range(1, 10) for j in range(1, 10) if i * j == X)

print(total - count * X)
```

**判分**：这类题没有「标准答案」可比。评测时把代码抽出来，放进 Docker 沙盒，用 43 组测试输入逐一运行（每组限时 6 秒），输出全部和预期一致才算对。这题 43 组全部通过。输入 472 token，输出 344 token。

## 三个样例放在一起看

| | GPQA-Diamond | AIME 2026 | LiveCodeBench v6 |
|---|---|---|---|
| 思考长度 | 866 字符 | 3317 字符 | 746 字符 |
| 输入 / 输出 token | 235 / 560 | 228 / 2127 | 472 / 344 |
| 判分依据 | 最后一行的字母 | `\boxed{}` 里的数值 | 43 组测试全部通过 |

几点读评测结果时要记住的：

- **判分只看最终回答的固定位置。** 推理过程写得再好，最后一行格式不对（GPQA）或者没写 `\boxed{}`（AIME），也是 0 分。训练后格式能力的退化，会直接表现为分数下降；
- **数学题的输出最长。** AIME 这道题输出 2127 token，是另外两道的好几倍。评测时的最大生成长度如果设得太短，长题会被截断、拿不到 `\boxed{}`，见[长度暴涨与熵坍缩](concepts.md)；
- **AIME 只有 30 题，一题就是 3.3 分。** 单次采样的分数波动很大，要多次采样取平均（如 avg@16）再比较；
- **代码题最难"蒙对"。** 选择题有 25% 的随机正确率，数学题可以猜，代码题要通过全部测试才算对。
