# 长度暴涨与熵坍缩

这是 OPD（以及 RL）训练中最常见的两种异常。它们在训练曲线上很容易被忽略，但会直接改变评测分数，所以读评测结果之前要先理解它们。

## 长度暴涨（length inflation）

### 是什么

训练进行到某个时刻，学生的回答长度突然快速上涨，而且涨了就回不来。典型过程是：

1. `response_length/mean` 开始持续上升；
2. 越来越多的回答写到最大长度被截断（截断率上升）；
3. 回答里出现大量重复：同一句话、同一段推导来回写；
4. 被截断的轨迹开始主导训练数据，验证集分数骤降。

论文里把最后这个阶段叫 **truncation collapse**（截断崩溃）。

### 为什么会在 OPD 里发生

| 原因 | 机制 |
|---|---|
| **师生的结束 token 不一致** | 比如学生用 `<\|endoftext\|>` 结束，教师用 `<\|im_end\|>`。教师觉得学生的结束 token 概率很低，逐 token 目标就会把它压下去，学生越来越"不肯停" |
| 自采样和蒸馏目标相互作用 | 学生自己生成训练数据，目标函数又隐式偏好长而重复的回答，两者形成正反馈 |
| 教师本身更啰嗦 | 学生在学教师的说话方式，教师写得长，学生也会写长 |
| 后段的教师信号不可靠 | 学生陷入重复后，教师仍给"局部接得上"的重复 token 较高概率，重复没有被惩罚 |

### 对评测分数的影响

- **截断 = 0 分**：AIME 的答案在 `\boxed{}` 里，GPQA 的答案在最后一行。回答被截断时这两样都还没写出来，直接判错，哪怕前面的推理都是对的；
- **评测设置会放大或掩盖它**：评测时的最大生成长度比训练时大，分数可能没怎么掉，但推理成本暴涨；比训练时小，分数会大幅下降；
- **分不清是"不会做"还是"写不完"**：只看准确率看不出来，要同时看平均输出长度和截断比例。

### 怎么发现

- 训练时：`response_length/mean`、`response_length/clip_ratio`（截断率）持续上升；
- 评测时：统计每个评测集的平均输出 token 数和"没有抽到答案"的比例，和训练前的模型对比。

### 怎么修

1. 先检查师生的结束 token 和 special token 是否一致：在概率层面把等价的结束 token 合并，并 mask special token。只扩大解码时的 stop 集合没有用；
2. 缩短最大生成长度，确认问题消失后再逐步放开；
3. 加参考模型的散度约束，或混入参考 rollout（StableOPD 的做法）；
4. 必要时叠加少量结果奖励，让"写完并答对"有回报。

详见[踩坑大全](../practice/pitfalls.md)。

## 熵坍缩（entropy collapse）

### 是什么

**熵**衡量模型在每个位置上"有多不确定"。对第 $t$ 个位置，

$$
H_t = -\sum_{v \in V} \pi_\theta(v \mid y_{<t}) \log \pi_\theta(v \mid y_{<t})
$$

训练日志里的 `actor/entropy` 是它在所有回答 token 上的平均值。

- 熵高：模型在很多候选 token 之间犹豫，回答多样；
- 熵低：模型几乎只选一个 token，回答高度确定；
- **熵坍缩**：熵在训练中迅速掉到接近 0，模型对每道题几乎总是给出同一个回答。

### 为什么会在 OPD 里发生

| 原因 | 机制 |
|---|---|
| reverse KL 本身是 mode-seeking | 它让学生集中到教师的一个模式上，天然会降低熵 |
| 学习率太大 | 每一步把高概率 token 推得更高，几步之内分布就变尖 |
| prompt 太单一 | 只用教师训练时见过的题，学生熵会灾难性地坍塌 |
| k1 的极端值主导更新 | 少数 $\lvert k_1 \rvert$ 很大的 token 产生很大的梯度 |

注意：熵缓慢下降是正常的，学生在变得更像一个确定的教师。问题在于**突然**、**大幅**地掉到接近 0。

### 对评测分数的影响

- **pass@1 可能不降，pass@k 会降**：每次都给同一个回答，多采几次也没有新机会。单次采样的分数看起来还行，但 avg@16 和 pass@16 之间的差距会缩小；
- **多次采样失去意义**：AIME 这类题要靠多次采样取平均来降低方差，熵坍缩后 16 次采样几乎一样，平均值不再可靠；
- **后续 RL 难以继续**：GRPO 需要组内有对有错才有信号，学生每次都给同一个答案，组内全对或全错，学不到东西。

### 怎么发现

- 训练时：`actor/entropy` 在很少的步数内跌到很低；
- 评测时：同一道题多次采样，看回答是否几乎相同；比较 pass@1 和 pass@k 的差距相对训练前是否明显缩小。

### 怎么修

1. 降学习率（例如 1e-6 → 5e-7）；
2. 收紧 `loss_max_clamp`、调小 `clip_ratio_high`，限制极端 token 的影响；
3. 在对齐教师的 prompt 之外，混入一定比例的 OOD prompt 维持多样性；
4. 需要多样性的任务（开放式生成），考虑 forward KL 或自适应散度，见[散度怎么选](../theory/divergence.md)。

## 两者对照

| | 长度暴涨 | 熵坍缩 |
|---|---|---|
| 先报警的指标 | `response_length/mean`、截断率 | `actor/entropy` |
| 回答的样子 | 很长、重复、写不完 | 很确定、多次采样几乎相同 |
| 对评测的主要影响 | 截断后抽不到答案，直接 0 分 | pass@k 和多次采样平均失去意义 |
| 第一步检查 | 师生结束 token 是否一致 | 学习率和 prompt 多样性 |

两者常常一起出现：模型陷入重复时，每个重复 token 的概率都很高，熵也很低。
